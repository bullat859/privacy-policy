02AccessibilityService API — Detailed Disclosure

Dynamic Edge Gesture Control utilizes Android's AccessibilityService API as a core foundational engine. In full compliance with Google Play's User Data Policy and Accessibility Policies for non-assistive utility apps, we provide the following comprehensive technical explanation:

Why AccessibilityService is Required

The AccessibilityService API is used exclusively to dispatch system-level navigation actions that cannot be executed through standard non-privileged Android APIs. These actions are triggered solely in response to deliberate, user-configured touch gestures on the device screen edges:

  • Simulating the hardware Back button action (GLOBAL_ACTION_BACK)
  • Returning to the device Home screen (GLOBAL_ACTION_HOME)
  • Opening the Recent / Overview Apps task switcher (GLOBAL_ACTION_RECENTS)
  • Pulling down the system Notification shade (GLOBAL_ACTION_NOTIFICATIONS)
  • Pulling down Quick Settings toggles (GLOBAL_ACTION_QUICK_SETTINGS)
  • Opening the system Power dialog (GLOBAL_ACTION_POWER_DIALOG)
  • Locking the device screen (GLOBAL_ACTION_LOCK_SCREEN on Android 9+)
  • Capturing a system screenshot (GLOBAL_ACTION_TAKE_SCREENSHOT on Android 9+)
  • Splitting the screen into multi-window mode (GLOBAL_ACTION_TOGGLE_SPLIT_SCREEN)
✅ Strict Anti-Surveillance Guarantee: Dynamic Edge Gesture Control does NOT use the AccessibilityService to:
  • Inspect, scrape, capture, read, or process on-screen content, text, images, or UI layouts.
  • Log, intercept, or record keystrokes, password entries, PIN codes, or any user input.
  • Monitor user activity across other applications, browsing history, or messaging chats.
  • Automate clicks, taps, or inputs on third-party application UIs without real-time user trigger.
  • Circumvent Android operating system security controls, user consent dialogs, or permissions.

Consent & User Control

In accordance with Android requirements, the AccessibilityService cannot be enabled automatically or programmatically by the application. The user must explicitly navigate to Android Settings → Accessibility → Downloaded Apps → Dynamic Edge Gesture Control and turn the toggle ON manually after reviewing the Android-provided security disclaimer dialog.

03Comprehensive Android Permissions Breakdown

Every permission declared in our AndroidManifest.xml serves an explicit, user-initiated functional purpose. We strictly adhere to the Android principle of minimal permission scope. No permission is declared speculatively or for future use. Below is a full disclosure of all declared permissions:

SYSTEM_ALERT_WINDOW — Display Over Other Apps

Renders interactive edge sliders, notch handles, volume overlays, and pie navigation menus over other running apps. User must explicitly grant via Settings.

WRITE_SETTINGS — Modify System Settings

Allows gestures to adjust device brightness, screen rotation lock, screen timeout duration, audio volume streams, and haptic feedback intensity profiles.

CAMERA — Camera Hardware

Accesses device camera exclusively for user-initiated gesture shortcut actions: one-touch camera shortcuts, QR/barcode scanning, and quick video recording memos. The camera utilizes standard Android camera APIs and is never activated passively or in the background without an explicit gesture trigger.

RECORD_AUDIO — Microphone

Accesses the microphone for user-initiated gesture triggers: voice command detection (on-device TTS/STT), audio memo recording, and ambient sound level detection for adaptive gesture sensitivity. Audio is never transmitted to remote servers.

ACCESS_FINE_LOCATION + ACCESS_BACKGROUND_LOCATION

Reads precise GPS coordinates to enable situational geo-fencing: automatically activating or deactivating specific gesture profiles based on user-defined geographic zones (e.g., "at home" profile vs. "at work" profile). Location is never uploaded or shared.

READ_CONTACTS — Single Contact Shortcut Reference Only

Strict High-Risk Permission Transparency: Dynamic Edge Gesture Control does not read, harvest, replicate, or store your address book in a local database, nor does it sync or upload contact records to any remote server or third party. Contacts access is utilized strictly via an on-demand picker solely when you explicitly map a "Quick-Dial" or "Direct-Message" gesture shortcut. The application holds only a local Android URI reference / phone number string for the single contact record you specifically selected for that gesture action.

CALL_PHONE — Direct Phone Call Shortcut

Direct User-Initiated Telephony: Governed as a sensitive permission, CALL_PHONE allows a configured gesture to initiate a phone call strictly to the pre-assigned contact number chosen by the user. Calls are never initiated automatically, covertly, or in the background. The action is triggered exclusively upon your deliberate edge gesture. The application does not read, monitor, log, or transmit your device call history or call duration records.

QUERY_ALL_PACKAGES — Package Visibility

Reads the list of installed applications on your device. Used exclusively to: (a) populate the app-picker list in gesture action configuration; and (b) enable app-specific gesture profile switching based on the active foreground application. App lists are processed entirely on-device and never transmitted.

VIBRATE — Haptic Feedback

Triggers device vibration motor for haptic confirmation feedback when gesture actions are executed. No vibration patterns are transmitted; all haptic output is local.

BLUETOOTH_CONNECT + BLUETOOTH_SCAN — Bluetooth

Detects Bluetooth connection state (connected headphones, car kit, speaker) to enable situational Bluetooth-aware gesture profiles (e.g., "car mode" when connected to a car Bluetooth device). No audio data, Bluetooth device addresses, or pairing keys are transmitted.

READ_MEDIA_AUDIO — Media Library Access

Accesses audio files on device storage so users can assign custom audio playback (music tracks, notification sounds) as gesture actions. Files are selected by the user; no media is uploaded.

FOREGROUND_SERVICE_CAMERA + FOREGROUND_SERVICE_MICROPHONE — Transient Execution

Strict Android 14+ Policy Compliance: Declares foreground service sub-types strictly required under Android 14+ when invoking camera and microphone hardware. These services are transient—activated exclusively during the exact momentary execution of a user-initiated camera shortcut, QR scan, or voice recognition session, and are immediately released upon completion. The application does not continuously hold camera or microphone hardware in the background, and always displays a visible, mandatory foreground service notification during execution.

SCHEDULE_EXACT_ALARM + USE_EXACT_ALARM

Allows the app to schedule time-based gesture triggers and automation routines at exact times. Used for scheduled profile switching (e.g., "night mode" at 10 PM) and repeating gesture automations. Required by Android 12+ for exact alarm scheduling.

REQUEST_IGNORE_BATTERY_OPTIMIZATIONS

Requests exclusion from Android's battery optimization system so the foreground gesture detection service is not killed by the OS during extended usage. Prevents missed gesture triggers when the device is in Doze mode.

WAKE_LOCK

Prevents the CPU from sleeping during active gesture recognition sessions initiated by the user. Released immediately when the gesture session ends to conserve battery.

POST_NOTIFICATIONS

Required by Android 13+ (API 33+) to display the persistent foreground service notification (mandatory for active Accessibility and camera/microphone foreground services) and to send optional user-configured gesture event alerts.

04Camera, Microphone & Media Privacy

⚠️ Anti-Covert Surveillance Declaration: Dynamic Edge Gesture Control does NOT engage in any form of covert, passive, background, or unauthorized surveillance using the camera or microphone. All camera and microphone activations are exclusively user-initiated via deliberate gesture triggers with explicit on-screen visual confirmation.

Camera Usage & One-Touch Shortcuts

The camera hardware is accessed only when the user configures and triggers a camera-based gesture shortcut action. The app relies on standard Android Camera/Camera2 platform APIs. Specific user-directed use cases include:

  • One-Touch Camera Capture: The user maps an edge swipe or hold gesture as a direct shortcut to snap a quick photo. The captured photo is immediately saved to the standard Android MediaStore / DCIM directory on the device with full user visibility. It is never uploaded to any remote server or third party.
  • Quick Video Memo: User assigns a gesture to begin a short video recording memo. The video file is stored directly in the device's public or app-specific media directory. It is never transmitted remotely.
  • QR / Barcode Scanner: Opens the camera in scan mode to read QR codes or barcodes. Scan results are displayed on-screen for the user to use. No scan history is persisted by the application.
  • Flashlight Torch Toggle: Activates/deactivates the rear camera flash LED as a torch. No camera preview or image capture occurs during torch-only operations.

All captured photos and videos remain in standard Android gallery directories and are subject to the user's own device backup settings (e.g., Google Photos automatic backup, Samsung Cloud). EDGE does not control or have insight into such device-level backup behaviors.

Microphone Usage

The microphone is accessed only under these strictly user-controlled conditions:

  • Voice Command Gesture Trigger: The user configures a gesture to activate a voice recognition session. Speech is processed entirely on-device using the Android Speech Recognition API (operating locally or via the user's selected default recognition engine, which may be Google, Samsung, or a third-party engine subject to that engine's own privacy policy).
  • Audio Memo Recording: User assigns a gesture to begin an audio memo recording. The resulting file is saved to app-private storage on-device and never transmitted by EDGE.
  • Ambient Sound Sensitivity: If the user enables adaptive gesture sensitivity based on ambient noise level, the microphone briefly samples background dBSPL without recording or storing any audio data.

Transient Foreground Service Policy

In strict compliance with Android 14+ (API 34+) Google Play foreground service policies: FOREGROUND_SERVICE_CAMERA and FOREGROUND_SERVICE_MICROPHONE are strictly transient. They are activated only at the exact instant a user triggers a camera capture or voice gesture, and terminate immediately once the action finishes. They are never held active indefinitely in the background, and an active foreground service notification is visibly maintained during their momentary runtime.
